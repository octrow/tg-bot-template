# 0006. Шаблон копируется, а не подключается библиотекой

Дата: 2026-10-08. Статус: принято. Решения 1, 4 и 6 плана выделения шаблона из исходного бота.

## Контекст

Шаблон выделен из рабочего бота, чтобы новые Telegram-боты начинались с готовой механики: режимы, пачки сообщений, лестница моделей, отзывы, журнал. Ботов ожидается два-три, и они независимы: у каждого свои режимы, тексты и сервер. У автора есть и общие Python-библиотеки (`pycommons`, `tg-toolkit`).

## Решение

- Новый бот - копия шаблона по чеклисту из README. Шаблон не библиотека и не copier-шаблон, механизма обновления копий нет.
- Новый режим - новый файл в `handlers/` по образцу демо-режима `echo.py`.
- Шаблон самодостаточен: свой git, не член uv workspace общих библиотек и не зависит от `pycommons` или `tg-toolkit`. Логгер бота устроен иначе, чем `pycommons.setup_logging` (контекст апдейта, маска секретов, файловый журнал сессий), а боты деплоятся на сервер, где этих библиотек нет.
- Python >= 3.12.

## Последствия

- Исправление в шаблоне не доходит до уже созданных ботов само: его переносят руками, если нужно.
- Ядро с общим API не проектируется заранее. Если ботов станет больше и общий код начнёт расходиться, вопрос о библиотеке открывается заново.
- Деплой бота - один каталог с `uv sync`, без внешних путей.
