# 0005. Скриншот распознаётся в текст один раз, а не передаётся каждой ступени

Дата: 2026-10-07. Статус: принято. Унаследовано из исходного бота.

## Контекст

Люди присылают скриншоты экранов и ошибок интерфейса, а бот читает только текст. Самый прямой путь - передавать картинку в каждый вызов модели. Но одна из запасных моделей лестницы (ADR-0003, `deepseek-v4-flash`) картинки не принимает, а в цикле с инструментами картинка пересылалась бы на каждом шаге и при каждой перепробе ступени.

## Решение

Одна модель, понимающая картинки, один раз переводит скриншот в текст (термин "Распознанный скриншот" в CONTEXT.md): весь видимый текст дословно, что это за экран и что выделено. Дальше подпись вместе с этим текстом идёт по обычному текстовому пути без изменений: пачка сообщений, режим, лестница.

Модели выбраны замером 07.10 в исходном боте на 14 настоящих скриншотах, два прогона: основная `google/gemini-3.1-flash-lite` (38/38 точных совпадений в обоих прогонах, p50 около 4 с), запасная при ошибке `google/gemini-3.8-flash` (38/38). `glm-5.3-flash` и `gpt-6-luna` отклонены, потому что искажали длинные id и хэши. Запасная того же производителя выбрана сознательно: тихая опечатка в id хуже, чем редкий общий сбой Google, а на сбой у бота есть понятный отказ. Бесплатные модели (`:free`) не используются: их провайдеры хранят запросы и обучаются на них. Модели меняет `TGBOT_VISION_MODELS`.

## Последствия

- Визуальные детали, которые не передаются текстом, теряются. Для экранов и ошибок это приемлемо, выделенное стрелками описывается словами.
- Ошибка распознавания id не ловится автоматически.
- Если лестница когда-нибудь станет целиком мультимодальной, решение можно пересмотреть. Распознанный скриншот при этом останется нужен для журнала.
