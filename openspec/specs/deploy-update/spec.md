# deploy-update Specification

## Purpose
Обновление работающего на сервере бота до текущей версии из GitHub выполняется одной командой, которая сама решает, что нужно переустановить и перезапустить, и проверяет, что сервис после этого жив.

## Requirements

### Requirement: Обновление одной командой

Репозиторий SHALL содержать исполняемый скрипт обновления в `deploy/`, который за один запуск: подтягивает код из GitHub в каталог установки, приводит установленный systemd-юнит к версии из репозитория, обновляет зависимости при необходимости, перезапускает сервис и проверяет его состояние. Код из GitHub SHALL забираться от имени пользователя сервиса и только быстрым перемоткой (`--ff-only`), чтобы расхождение с origin не превращалось в merge-коммит на сервере.

#### Scenario: Обычное обновление

- **WHEN** администратор запускает скрипт обновления на сервере, где есть новые коммиты в origin
- **THEN** код обновлён до origin, сервис перезапущен, в выводе указана версия, на которую обновились (короткий хеш и заголовок коммита)

#### Scenario: Обновлять нечего

- **WHEN** скрипт запускается, когда локальная копия уже совпадает с origin
- **THEN** скрипт отрабатывает без ошибки и сервис остаётся работоспособным

#### Scenario: Расхождение с origin

- **WHEN** локальная история разошлась с origin и перемотка невозможна
- **THEN** скрипт останавливается с ненулевым кодом до перезапуска сервиса, не оставляя сервис в промежуточном состоянии

### Requirement: Юнит и зависимости синхронизируются из репозитория

Скрипт SHALL сравнивать установленный systemd-юнит с версией из репозитория и при отличии заменять его с перезагрузкой конфигурации systemd, сообщая об этом в выводе. Зависимости SHALL переустанавливаться, когда изменилось объявление зависимостей проекта, и SHALL NOT переустанавливаться, когда оно не менялось.

#### Scenario: Юнит изменился в репозитории

- **WHEN** версия юнита в репозитории отличается от установленной
- **THEN** установленный юнит заменён версией из репозитория, конфигурация systemd перезагружена, в выводе сказано, что юнит обновлён

#### Scenario: Юнит не менялся

- **WHEN** установленный юнит совпадает с версией из репозитория
- **THEN** файл не трогается и перезагрузка конфигурации systemd не выполняется

#### Scenario: Изменились зависимости

- **WHEN** обновление принесло изменения в объявлении зависимостей проекта
- **THEN** зависимости переустановлены в окружение сервиса до перезапуска

### Requirement: Результат обновления проверяется

После перезапуска скрипт SHALL убедиться, что сервис активен, и при неуспехе SHALL завершиться с ненулевым кодом, показав, где смотреть причину (последние строки журнала сервиса).

#### Scenario: Сервис поднялся

- **WHEN** после перезапуска сервис активен
- **THEN** скрипт сообщает об успешном обновлении и завершается с нулевым кодом

#### Scenario: Сервис не поднялся

- **WHEN** после перезапуска сервис не активен
- **THEN** скрипт печатает последние строки журнала сервиса и завершается с ненулевым кодом

### Requirement: Локальные настройки сервера живут в drop-in

Документация SHALL предупреждать, что правки установленного юнита затираются обновлением, и указывать drop-in-каталог systemd как место для серверных значений.

#### Scenario: Администратор читает инструкцию по обновлению

- **WHEN** администратор открывает документацию по деплою
- **THEN** там одна команда обновления и явное указание, что локальные правки юнита нужно держать в drop-in-файле, иначе они будут потеряны
