# command-menu Specification

## Purpose
Нативное меню команд Telegram в строке ввода: пользователь видит доступные команды бота с краткими описаниями (кнопка "Меню" и автодополнение по "/"), без обращения к README или тексту /start.

## Requirements

### Requirement: Регистрация меню команд при старте

Бот SHALL при запуске приложения регистрировать в Telegram список своих команд с
краткими описаниями для каждого поддерживаемого языка (русский и английский),
чтобы пользователь видел меню на языке своего Telegram-клиента. Русский набор
SHALL регистрироваться как набор по умолчанию, английский - дополнительно, для
`language_code = "en"`.
Набор по умолчанию - это меню пользователя без доступа (чужого или после
`/deny`) - SHALL содержать только `/whoami`, `/request_access` и `/language`:
показывать человеку команды, на которые он получит отказ, нельзя.
Рабочее меню допущенного пользователя SHALL содержать `/start`, `/help`, команды режимов из
реестра (`handlers.registry`, в шаблоне `/echo`) сразу после `/help`, затем `/support` и `/language`, и
SHALL NOT содержать `/whoami` и `/request_access`. Новый режим попадает в рабочее меню записью в реестре,
без правки списка команд.
Команды, убранные из меню, SHALL продолжать работать.
Описание каждой команды SHALL браться из `CMD_DESCRIPTIONS` локали; описание `/echo` говорит, что бот
повторяет текст.

#### Scenario: Меню доступно после запуска

- **WHEN** приложение бота запустилось, и меню открывает пользователь не из allowlist
- **THEN** он видит только `/whoami`, `/request_access`, `/language` - каждая с
  непустым кратким описанием

#### Scenario: Английское меню

- **WHEN** приложение бота запустилось, а пользователь открывает меню в
  англоязычном Telegram-клиенте
- **THEN** он видит тот же набор команд с англоязычными описаниями

#### Scenario: Команда режима в меню

- **WHEN** допущенный пользователь открывает меню команд
- **THEN** в нём есть `/echo` с описанием режима Эхо, сразу после `/help`

#### Scenario: Ошибка регистрации не роняет бота

- **WHEN** вызов регистрации команд для любой из локалей завершился ошибкой
  (сеть, Bot API)
- **THEN** бот продолжает запуск и обрабатывает сообщения; ошибка фиксируется в
  логе

#### Scenario: Опечатка в команде

- **WHEN** допущенный пользователь отправляет несуществующую команду, например `/whomai`
- **THEN** бот отвечает, что такой команды нет, и называет `/help`; событие `unknown_command` пишется в журнал

#### Scenario: Убранная из меню команда работает

- **WHEN** допущенный пользователь вводит `/whoami` вручную
- **THEN** бот отвечает, как раньше

### Requirement: Разделение команд пользователя и админа

Меню SHALL быть трёх уровней: ограниченное (набор по умолчанию), рабочее
(допущенный пользователь) и максимальное (админ: рабочее меню плюс команды
администрирования `/allow`, `/deny`, `/users`, `/cost`, `/cache_clear`,
`/logs`, `/feedback`). Рабочее меню SHALL ставиться персонально
чату пользователя при старте бота для всех из allowlist и при `/allow` (в том
числе одобрением заявки на доступ). При `/deny` персональное меню SHALL
заменяться ограниченным набором. При смене языка через `/language` персональное
меню SHALL пересобираться на новом языке. Ошибка установки меню SHALL NOT
отменять `/allow`, `/deny` или смену языка.

#### Scenario: Обычный пользователь

- **WHEN** пользователь из allowlist, не админ, открывает меню команд
- **THEN** он видит рабочее меню, без команд администрирования и без `/whoami`, `/request_access`

#### Scenario: Админ

- **WHEN** пользователь входит в `ADMIN_USER_IDS`
- **THEN** для его чата зарегистрировано максимальное меню: рабочее плюс команды администрирования

#### Scenario: Доступ выдан

- **WHEN** админ выполнил `/allow` для пользователя
- **THEN** у этого пользователя рабочее меню вместо ограниченного

#### Scenario: Доступ отозван

- **WHEN** админ выполнил `/deny` для пользователя
- **THEN** у этого пользователя снова ограниченное меню

#### Scenario: Смена языка

- **WHEN** допущенный пользователь выбрал английский через `/language`
- **THEN** его рабочее меню показано с английскими описаниями
